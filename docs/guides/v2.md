# Nado Python SDK v2 (`2.0.0`)

This release modernizes the SDK around **Pydantic v2** and expands API coverage
toward parity with the TypeScript SDK. This document covers what changed, what
(if anything) consumers need to do, and the new capabilities.

## TL;DR for consumers

- The SDK now requires **Pydantic `>=2.7`** (previously `<2.0`). This is the only
  hard dependency change.
- The public surface is unchanged: model `.dict()` / `.json()` still work and
  still omit `None` fields by default, clients are constructed the same way, and
  request/response shapes on the wire are identical.
- If your own code pinned `pydantic<2`, that pin must be lifted to install this
  release.

## Pydantic v1 → v2 migration

The migration is internal; it does not change the SDK's request/response
serialization. The notable mechanics:

| Area | v1 | v2 |
| --- | --- | --- |
| Base serialization | `.dict()` / `.json()` overrides | delegate to `model_dump` / `model_dump_json` |
| Validators | `@validator` / `@root_validator` | `@field_validator` / `@model_validator` |
| Model config | `class Config:` | `model_config = ConfigDict(...)` |
| `Optional[X]` fields | implicitly defaulted to `None` | explicit `= None` added everywhere |
| Discriminator fields | `type = "..."` (untyped) | `type: str = "..."` (annotated) |
| URL fields | `AnyUrl` (a `str` subclass) | `str` + URL-format validation |
| `conlist(min_items=...)` | — | `conlist(min_length=...)` |

### Behaviors deliberately preserved

`NadoBaseModel` sets three config flags so v2 matches v1 semantics exactly:

- **`serialize_as_any=True`** — request models swap a field's value for a
  differently shaped model inside a validator (e.g. a `*Params` field becomes a
  `TxRequest`). v1 serialized the runtime value; v2 would otherwise serialize by
  the declared type and drop fields. This flag restores duck-typed serialization.
- **`coerce_numbers_to_str=True`** — the server returns numbers for some
  string-typed fields (`chain_id`, nonces, x18 amounts); v1 coerced them, v2 is
  strict by default.
- **`revalidate_instances="always"`** — restores v1 `parse_obj` semantics so
  passing a model instance through `model_validate` yields a fresh, independent
  copy. Clients rely on this (e.g. `place_order` normalizes its input and mutates
  the result; the caller's params object must not be affected across calls).

### Test coverage

`tests/test_pydantic_v2_migration.py` pins each of the behaviors above so the
migration cannot silently regress. The full suite passes on Pydantic v2 with no
deprecation warnings emitted from the package.

## New in v2

### WebSocket support (`nado_protocol.ws`)

Synchronous clients for the gateway WebSocket endpoints, built on
`websocket-client`:

- **`NadoWebSocketClient`** — the `/ws` endpoint: send queries and (signed)
  executes over a socket using the same envelopes as the HTTP API.
- **`NadoSubscriptionClient`** — the `/subscribe` endpoint: subscribe to market
  and account streams, plus `list` / `ping` / `time` / `authenticate` control
  messages.
- **Stream params** — `TradeStream`, `BestBidOfferStream`, `BookDepthStream`,
  `FillStream`, `PositionChangeStream`, `OrderUpdateStream`, `LiquidationStream`,
  `LatestCandlestickStream`, `FundingPaymentStream`, `FundingRateStream`,
  `AllBboStream`.
- **Pure message builders** in `nado_protocol.ws.messages` for callers that
  manage their own socket.

```python
from nado_protocol.ws import NadoSubscriptionClient, TradeStream

with NadoSubscriptionClient("https://gateway.prod.nado.xyz/v1") as ws:
    ws.subscribe(TradeStream(product_id=1))
    for event in ws.listen():
        print(event)
```

The wire protocol (envelopes, stream renames, event shapes) matches the gateway
`/ws` + `/subscribe` endpoints.

### Expanded HTTP coverage

Parity additions landed so far:

- **Engine executes:** `place_orders` (batch), `transfer_quote`, `withdraw_collateral_v2`.
- **Engine queries:** `get_market_prices` (batch), `get_insurance`, `get_max_nlp_burnable`.
- **Engine edge/cached client** (`EngineEdgeQueryClient`): cached prices, symbols,
  contracts, status, all-products, health-groups, BBO history, plus `ping`/`time`.
- **Engine web client** (`EngineWebClient`): `/ip` block status + country code,
  `/cf-check` Cloudflare-challenge detection, `/time`.
- **Indexer queries:** `get_ink_airdrop`, `get_sequencer_backlog`,
  `get_subaccount_dda`, `get_points`, `get_private_alpha_choice`,
  `get_multi_perp_prices`, `get_nlp_snapshots`, `get_fast_withdrawal_signature`,
  `get_edge_candlesticks`, `get_edge_market_snapshots`.
- **Indexer leaderboard + social:** `get_leaderboard`,
  `get_leaderboard_participant`, `get_leaderboard_contests`,
  `get_leaderboard_registrations`, `list_social_accounts`, plus the EIP-712
  signed writes `register_leaderboard`, `connect_social_account`,
  `revoke_social_account`.
- **Indexer pagination:** `get_paginated_subaccount_orders`,
  `get_paginated_subaccount_events` (+ `collateral` / `nlp` / `settlement` /
  `liquidation` event subsets), `get_paginated_subaccount_match_events`,
  `get_paginated_subaccount_interest_funding_payments`,
  `get_paginated_leaderboard`.
- **High-level passthroughs:** `spot.withdraw_v2`, `spot.transfer_quote`,
  `market.get_latest_market_prices`.

Further endpoints toward full TypeScript-SDK parity are tracked in
[`feature-parity.md`](./feature-parity.md).

## Verification

Everything is unit-tested with mocked transport (offline). For live verification
against a running gateway/engine/indexer, run the sanity scripts (they read
`CLIENT_MODE` + `SIGNER_PRIVATE_KEY` from `.env`):

```bash
poetry run engine-sanity     # engine queries/executes, edge + web clients
poetry run indexer-sanity    # indexer queries incl. the v2.0.0 additions
poetry run ws-sanity         # WebSocket /ws + /subscribe streaming
poetry run trigger-sanity
poetry run client-sanity
```

The engine and indexer sanity scripts exercise the new v2.0.0 endpoints at the
end of their runs.
